# 异常应急流程

> 账号异常时，**按顺序** 执行。不要跳步，不要慌。

## 阶段 0：先别动（30 秒）

- [ ] 不要立刻点"重试登录"10 次
- [ ] 不要立刻换代理节点
- [ ] 不要立刻找客服
- [ ] 截图保存异常现象 + 时间

## 阶段 1：识别异常类型（2 分钟）

按 `docs/05-异常自查清单.md` 第一节对照，确认是哪类：

- 网络 / 设备画像异常 → 阶段 2A
- 限流 / 脚本画像 → 阶段 2B
- 会话 / 登录异常 → 阶段 2C
- 支付 / 订阅异常 → 阶段 2D
- 完全封禁 → 阶段 4

## 阶段 2：自查与修复

### 2A 网络 / 设备

- [ ] 回到主力网络 + 主力设备
- [ ] 完成平台验证（邮箱 / 手机码）
- [ ] 登出其他设备会话
- [ ] 保持稳定 7 天

### 2B 限流 / 脚本画像

- [ ] 停并发，回单会话
- [ ] 用量降回档位正常范围
- [ ] 停网页自动化脚本
- [ ] 多样化使用，避开敏感领域扎堆
- [ ] 等额度滚动刷新

### 2C 会话 / 登录

- [ ] 登出所有其他会话
- [ ] 改密码（强制 session 失效）
- [ ] 主力设备重新登录一次
- [ ] 开二步验证
- [ ] 不再共享 session

### 2D 支付 / 订阅

- [ ] 先查卡状态（银行 App）
- [ ] 排除余额 / 风控
- [ ] Console 更新支付方式
- [ ] 重试扣款 **一次**
- [ ] 不疯狂点重试

## 阶段 3：观察期（24–48 小时）

- [ ] 自查修复后，正常使用，不刻意压测
- [ ] 观察异常是否复现
- [ ] 仍异常 → 阶段 4

## 阶段 4：走官方申诉

按 `docs/06-申诉与恢复.md`：

- [ ] 准备材料（邮箱 / 姓名 / 订阅 / 异常时间 / 自查记录）
- [ ] 用模板写邮件，一次给齐
- [ ] 只开一个 ticket
- [ ] 耐心等 1–5 工作日

## 阶段 5：最坏情况

确认不可恢复：

- [ ] 取消订阅
- [ ] 撤销所有 API key
- [ ] 解绑第三方集成
- [ ] 备份需要的对话 / 项目
- [ ] 用 **新真实身份** 合规注册新账号（不复用旧画像）

## 禁止动作清单

```
❌ 疯狂点重试登录 / 重试扣款
❌ 立刻换代理节点
❌ 找"代解封"服务
❌ 多渠道同时开 ticket
❌ 威胁客服 / 情绪化沟通
❌ 用旧账号身份 / 支付 / 设备画像注册新账号
```
