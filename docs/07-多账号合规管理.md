# 07 · 多账号合规管理

> 个人确实有"工作 + 个人"或"开发 + 创作"多账号的需求。这篇讲怎么 **合规** 管理多个账号，而不是怎么搞账号农场。

## 一、什么算合规多账号

合规的多账号 = **不同真实身份、不同用途、各自独立使用**。

例如：
- A 账号：本人身份 + 本人支付，用于个人学习；
- B 账号：公司身份 + 公司支付，用于工作（公司有Anthropic 账号）。

不合规的"多账号"：
- 同一人用同一身份注册多账号绕限额；
- 一套支付卡绑多个账号；
- 多账号共享同一 IP / 设备画像批量使用。

后者就是账号农场，Anthropic 明确禁止，封号连锁反应。

## 二、身份隔离

每个账号应有：

| 维度 | 要求 |
|------|------|
| 注册邮箱 | 不同邮箱（不同持有人） |
| 注册姓名 | 真实持有人姓名 |
| 手机号 | 该持有人本人号码 |
| 支付方式 | 该持有人本人卡 |
| 账单地址 | 与该持有人一致 |

身份维度重叠 = 强关联信号，一个出事，全连锁。

## 三、环境隔离

合规多账号的另一个关键是 **环境不要混**：

- 不同账号尽量用不同设备 / 不同浏览器 profile；
- 至少不要在同一浏览器同一 session 切换账号使用；
- 网络出口尽量分开（A 账号用 A 网络，B 账号用 B 网络）；
- 不要在短时间内同一设备切换登录两个账号。

## 四、用途隔离

- 每个账号有 **清晰的用途**，不要交叉；
- 工作账号只做工作，个人账号只做个人；
- 不要把工作账号的 API key 拿去跑个人项目。

用途隔离既是合规要求，也是出事时的止损——一个账号出问题不影响其他。

## 五、API key 管理

如果多账号都有 API 访问：

- 每个 organization 的 key **独立**，不混用；
- key 存在各自的 secret manager / 环境变量，不混在一个配置里；
- 调用 IP 隔离（不同 organization 用不同服务器 IP）；
- 用量告警各自设置。

## 六、什么情况建议合并，不要拆

如果你只是"想多跑点量"而拆账号，**不要拆**：

- 拆账号绕限额 = 典型的风控触发模式；
- 直接升档到 Max 比拆 5 个 Pro 安全得多、便宜得多、稳定得多；
- Max $100 档的用量足够覆盖大多数重度个人用户。

账号数量 ∝ 风控风险。能用一个账号解决就别开两个。

## 七、团队 / 公司场景

如果是团队共享 Claude：

- 用 **Anthropic 的团队 / 企业方案**（Team / Enterprise plan），而不是每人开个人账号互相共享；
- 团队 plan 有正规的多席位管理，风控也在合规框架内；
- 不要搞"一个 Pro 账号全公司共享 cookie"——必封。

## 八、多账号合规快查表

```
✅ 每个账号独立真实身份 + 独立支付
✅ 环境（设备 / 网络 / 浏览器）隔离
✅ 用途清晰不交叉
✅ API key 按 organization 隔离
✅ 能升档就别拆账号

❌ 同身份多账号绕限额
❌ 一卡绑多账号
❌ 多账号共享 IP / 设备画像
❌ 团队共享个人账号 cookie
❌ 账号农场
```

## 小结

多账号本身不违规，违规的是"用多账号绕限制"。真实身份独立、环境独立、用途清晰，才是合规的多账号管理。
