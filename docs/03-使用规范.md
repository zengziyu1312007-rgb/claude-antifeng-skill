# 03 · 使用规范

> 风控的另一半权重在看"你怎么用"。这一篇管住你的手。

## 一、频率与档位匹配

### 1. 不同档位的"正常用量"

| 档位 | 每日对话量参考 | 并发 |
|------|---------------|------|
| Free | 少量，间歇 | 1 会话 |
| Pro ($20) | 中等，日常工作 | 1–2 会话 |
| Max ($100 / $200) | 较高，重度使用 | 2–3 会话 |

风控看的不是绝对数量，而是 **你的用量是否匹配你 paying 的档位**。

- Free 账号跑出 Max 级别的量 = 异常；
- Pro 账号 24 小时不间断调用 = 自动化脚本画像；
- Max 账号在档位上限内合理使用 = 正常。

### 2. 并发是强信号

- 同一账号 **同时** 在多个会话发消息 = 强异常信号；
- Claude 本身对并发有限制，频繁撞限 = 风控会注意；
- 真实人不会同时开 5 个会话并行打字。

### 3. 节奏要像人

- 真实人有思考间隔、有上下文阅读时间；
- 脚本画像是：请求 → 0.1s 后下一个请求 → 0.1s 后下一个；
- 即使用 API 做自动化，也加合理的间隔和退避，不要压满速率。

## 二、API 速率与退避

### 1. 守住官方速率限制

Anthropic 对每个账号 / 每个 model 有 RPM（每分钟请求数）、TPM（每分钟 token 数）、ITPM（输入 token/分钟）限制。

- 在 [Console → Settings → Limits](https://console.anthropic.com/settings/limits) 查看当前档位；
- 不要长期顶格跑——顶格跑 = 资源占用画像异常；
- 留 20–30% 余量是健康的。

### 2. 必须实现退避重试

碰到 429（rate limit）或 529（overloaded）时：

```
1. 不要立即重试
2. 指数退避：1s → 2s → 4s → 8s → 16s
3. 抖动：每个退避时间加随机 0–500ms
4. 重试上限：3–5 次后放弃，记日志
```

疯狂重试 429 = 风控系统的"滥用"信号。

### 3. 用量监控

- Console 里有 Usage 页面，定期看；
- 设置 Anthropic 的用量告警（spend threshold）；
- 突然飙升的用量要么是 bug，要么是 key 泄露，都要立刻处理。

## 三、订阅档位切换

### 1. 不要频繁升降级

- 一周内 Pro → Max → Pro → Max 反复切 = 支付与使用画像异常；
- 选好档位，稳定使用一段时间；
- 降级前先把当前周期用完，不要刚升级立刻降。

### 2. 支付失败不要反复试

- 扣款失败 → 先去查卡（余额、限额、风控）→ 解决后再重试；
- 不要在支付失败状态下反复点"重试扣款"，每次失败都是一次风控事件；
- 反复失败 + 反复重试 = 高频异常信号。

## 四、登录与会话

### 1. 不要频繁登出登入

- 登录态保持是正常用户特征；
- 每天登出再登入 N 次 = 异常会话行为。

### 2. 不要共享登录态

- 把 cookie / session token 给别人用 = 账号共享；
- 多端登录 OK，但同时多人用同一 session = 强异常。

### 3. 启用二步验证

- Anthropic 账号支持二步验证，开启；
- 二步验证 = "真实用户在保护账号"的强信号，反而降低风控权重。

## 五、使用规范快查表

```
✅ 用量匹配订阅档位
✅ 单会话 / 低并发
✅ 人的节奏，有思考间隔
✅ API 留 20–30% 余量 + 指数退避
✅ 稳定档位，不频繁切换
✅ 保持登录态 + 开 2FA

❌ Free 跑 Max 的量
❌ 多会话并发狂发
❌ 顶格跑速率 + 疯狂重试 429
❌ 一周内反复升降级
❌ 支付失败反复点重试
❌ 共享 cookie / session
```

## 小结

频率和节奏暴露"你是不是真人在用"。把用量压在档位合理区间，像人一样有间隔地用，比任何技巧都管用。
